1→Snowpark|Snowflake's developer framework for building data pipelines and ML workflows using Python, Java, or Scala; executes inside Snowflake's compute, bringing code to the data.|framework
2→Snowpark DataFrame|A lazy-evaluated distributed data structure in Snowpark representing a query against Snowflake data; transformations accumulate without execution until an action like .show() or .collect() is called.|Snowpark concept
3→Lazy Evaluation|A Snowpark principle where DataFrame transformations are not executed until explicitly triggered by an action; enables query plan optimization before execution.|Snowpark concept
4→session.table()|Snowpark method to load a Snowflake table as a DataFrame without pulling data to the local machine. Example: df = session.table("DB.SCHEMA.TABLE")|Snowpark method
5→session.sql()|Snowpark method to execute arbitrary SQL and return the result as a Snowpark DataFrame. Example: df = session.sql("SELECT * FROM table LIMIT 5")|Snowpark method
6→df.write.save_as_table()|Snowpark method to persist a DataFrame back to a Snowflake table. Example: df.write.save_as_table("DB.SCHEMA.TABLE", mode="append")|Snowpark method
7→df.filter()|Snowpark DataFrame method filtering rows by a condition, equivalent to SQL WHERE. Can be chained with .select(). Example: df.filter(col("TRUCK_BRAND_NAME") == "Freezing Point")|Snowpark method
8→COPY INTO|Batch ingestion command loading data from a stage into a Snowflake table; load history tracked in ACCOUNT_USAGE.COPY_HISTORY. Syntax: COPY INTO db.schema.table FROM @stage/path/;|ingestion command
9→Snowpipe|Snowflake's continuous, event-driven ingestion service that automatically loads new files arriving in a stage using cloud storage event notifications (AUTO_INGEST=TRUE).|ingestion service
10→CREATE PIPE|Creates a Snowpipe for continuous ingestion. Syntax: CREATE PIPE db.schema.pipe AUTO_INGEST=TRUE AS COPY INTO table FROM @stage;|Snowpipe command
11→STORAGE INTEGRATION|A Snowflake object (TYPE=EXTERNAL_STAGE, STORAGE_PROVIDER=S3) that securely stores IAM credentials for external stages used by Snowpipe; described with DESCRIBE INTEGRATION to retrieve ARN values needed in AWS.|data engineering
12→Stream|A Snowflake CDC (Change Data Capture) object on a table that records all DML changes (inserts, updates, deletes) since the last time the stream was read. Syntax: CREATE STREAM stream_name ON TABLE table;|data engineering
13→Task|A Snowflake object that executes a SQL statement or stored procedure on a defined schedule; used to automate pipeline orchestration. Syntax: CREATE TASK name WAREHOUSE=wh SCHEDULE='1 minute' AS SQL_STATEMENT;|data engineering
14→Serverless Task|A Snowflake task variant that uses Snowflake-managed compute instead of a named warehouse; billed based on actual compute consumed.|data engineering
15→ACCOUNT_USAGE.COPY_HISTORY|Snowflake metadata view in the SNOWFLAKE database tracking all COPY INTO load operations; includes file names, error counts, status, and load timestamps.|metadata view
16→Observability|The ability to monitor Snowflake pipeline health using alerts and notifications, logs and event tables, and the Visual DAG viewer in the Snowflake UI.|data engineering concept
