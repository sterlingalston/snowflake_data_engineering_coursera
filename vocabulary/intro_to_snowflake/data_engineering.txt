1→SNOWFLAKE DATA ENGINEERING PIPELINE|The four stages of data engineering in Snowflake: Ingestion → Transformation → Orchestration → Observability.|data engineering
2→COPY INTO|Batch ingestion command that loads data from a stage into a table. Example: COPY INTO db.schema.table FROM @db.schema.stage/path/;|ingestion
3→BATCH INGESTION|Loading data in discrete chunks using COPY INTO from a stage. Contrasted with streaming ingestion via Snowpipe.|ingestion
4→STORAGE INTEGRATION|A Snowflake object that securely connects to an external cloud storage provider (e.g., S3) without embedding credentials. Example: CREATE OR REPLACE STORAGE INTEGRATION S3_role_integration TYPE=EXTERNAL_STAGE STORAGE_PROVIDER=S3 ENABLED=TRUE STORAGE_AWS_ROLE_ARN='...' STORAGE_ALLOWED_LOCATIONS=('s3://bucket/');|ingestion
5→DESCRIBE INTEGRATION|Shows properties of a storage integration, including the STORAGE_AWS_IAM_USER_ARN and STORAGE_AWS_EXTERNAL_ID needed to configure trust in AWS IAM. Example: DESCRIBE INTEGRATION S3_role_integration;|ingestion
6→SNOWPIPE|Continuous/streaming ingestion service. Automatically loads data from a stage into a table as new files arrive, using AUTO_INGEST=TRUE and event notifications (e.g., S3 → SQS). Example: CREATE PIPE db.schema.pipe AUTO_INGEST=TRUE AS COPY INTO table FROM @stage;|ingestion
7→CREATE PIPE|DDL to create a Snowpipe. Example: CREATE PIPE S3_db.public.S3_pipe AUTO_INGEST=TRUE AS COPY INTO S3_db.public.S3_table FROM @S3_db.public.S3_stage;|ingestion
8→AUTO_INGEST|Snowpipe parameter (TRUE/FALSE) that enables event-based automatic loading when new files land in the stage.|ingestion
9→SHOW PIPES|Lists all pipes in the current database/schema.|ingestion
10→ALTER PIPE ... SET PIPE_EXECUTION_PAUSED|Pauses or resumes a Snowpipe. Example: ALTER PIPE S3_pipe SET PIPE_EXECUTION_PAUSED = TRUE;|ingestion
11→SNOWPARK DATAFRAMES|A library (Python/Java/Scala) for transforming data inside Snowflake without moving it out. DataFrames are evaluated lazily — transformations are not executed until an action like .show() or .collect() is called.|data engineering
12→LAZY EVALUATION|Snowpark DataFrames do not execute transformations until explicitly triggered (e.g., df.show(), df.collect(), df.write). This allows Snowflake to optimize the full query plan.|data engineering
13→SESSION.TABLE()|Snowpark method to load a Snowflake table as a DataFrame. Example: df = session.table("DB.SCHEMA.TABLE")|data engineering
14→SESSION.SQL()|Snowpark method to run a SQL string and return a DataFrame. Example: df = session.sql("SELECT * FROM table LIMIT 5")|data engineering
15→DF.FILTER()|Snowpark DataFrame method to filter rows. Example: df.filter(col("TRUCK_BRAND_NAME") == "Freezing Point")|data engineering
16→DF.SELECT()|Snowpark DataFrame method to select specific columns. Example: df.select(col("MENU_ITEM_NAME"), col("ITEM_CATEGORY"))|data engineering
17→DF.WRITE.SAVE_AS_TABLE()|Snowpark method to save a DataFrame as a Snowflake table. Supports modes: append, overwrite, etc. Example: df.write.save_as_table("DB.SCHEMA.TABLE", mode="append")|data engineering
18→STREAM|A Snowflake object created on a table that tracks DML changes (inserts, updates, deletes) since the last time the stream was consumed. Example: CREATE STREAM sales_stream ON TABLE sales;|data engineering
19→TASK|A Snowflake object that executes SQL or a stored procedure on a schedule (cron or interval). Often used together with streams for CDC pipelines. Example: CREATE TASK sales_task WAREHOUSE=small SCHEDULE='1 minute' WHEN system$stream_has_data('sales_stream') AS INSERT INTO new_sales SELECT ...|data engineering
20→SERVERLESS TASKS|Tasks that run without a dedicated warehouse, using Snowflake-managed compute. Billed per second of compute used.|data engineering
21→OBSERVABILITY (data engineering)|Tools in Snowflake for monitoring pipelines: Alerts and Notifications, Logs and Events (event tables), and the Visual DAG viewer in the Snowflake UI.|data engineering
22→VISUAL DAG VIEWER|Snowflake UI feature that shows task dependency graphs (directed acyclic graphs) for monitoring orchestrated pipelines.|data engineering
23→EVENT TABLE|A Snowflake table used to capture log and event data from Snowflake functions, procedures, and applications for observability.|data engineering
24→ACCOUNT_USAGE.COPY_HISTORY|View that records the history of all COPY INTO operations in the account. Useful for auditing data loads. Example: SELECT file_name, error_count, status, last_load_time FROM snowflake.account_usage.copy_history ORDER BY last_load_time DESC LIMIT 10;|data engineering
