1→Snowflake Platform Architecture|Three-layer, cloud-native data platform: Optimized Storage (bottom), Elastic Multi-Cluster Compute (middle), and Cloud Services (top), unified by Snowgrid for cross-cloud operations.|architecture
2→Optimized Storage|Snowflake's storage layer providing un-siloed access to data, easy data management at scale, and flexibility and interoperability across formats.|architecture layer
3→Elastic Multi-Cluster Compute|Snowflake's compute layer that powers AI, apps, and analytics through a single engine; supports SQL, Python, Java, and Scala; runs preferred libraries in Snowpark; brings development to the data.|architecture layer
4→Cloud Services|Snowflake-managed layer that automates costly and complex operations, provides unified built-in governance, and enables access to built-in AI models, LLMs, and vector search functionality.|architecture layer
5→Snowgrid|Snowflake's cross-cloud layer enabling cross-cloud collaboration with no ETL, cross-cloud governance to minimize risk, and cross-cloud business continuity to eliminate disruptions.|architecture layer
6→Virtual Warehouse|A named cluster of compute resources in Snowflake used to execute queries and DML; billed by credit consumption; can be resized, suspended, and resumed independently of storage.|warehouse
7→WAREHOUSE_SIZE|Parameter for CREATE/ALTER WAREHOUSE setting compute capacity (XSMALL, SMALL, MEDIUM, LARGE, XLARGE, etc.); larger sizes consume more credits per hour.|warehouse parameter
8→Multi-Cluster Warehouse|A Snowflake warehouse that scales horizontally by automatically adding compute clusters when concurrency demands increase; configured with MIN_CLUSTER_COUNT and MAX_CLUSTER_COUNT.|warehouse
9→MAX_CLUSTER_COUNT|Warehouse parameter defining the maximum number of compute clusters that can run concurrently in a multi-cluster warehouse. Example: CREATE WAREHOUSE vino MAX_CLUSTER_COUNT = 3;|warehouse parameter
10→AUTO_SUSPEND|Warehouse parameter specifying the number of seconds of inactivity before Snowflake automatically suspends the warehouse to save credits. Example: ALTER WAREHOUSE wh SET AUTO_SUSPEND = 180;|warehouse parameter
11→AUTO_RESUME|Warehouse parameter (TRUE/FALSE) controlling whether the warehouse automatically resumes when a query is submitted. Example: ALTER WAREHOUSE wh SET AUTO_RESUME = FALSE;|warehouse parameter
12→Stage|A Snowflake object pointing to a file storage location used to load or unload data; three types: User (@~), Table (@%), and Named (external or internal).|data loading
13→User Stage|Notation: @~; a personal internal stage auto-created for each Snowflake user; can only be used by that specific user; cannot be dropped.|stage type
14→Table Stage|Notation: @%table_name; an internal stage automatically associated with a specific table; cannot be shared or dropped.|stage type
15→Named Stage|An explicitly created internal or internal stage that can be shared across multiple users and tables. Example: CREATE STAGE db.schema.stage_name URL='s3://bucket/';|stage type
16→File Format|A Snowflake object defining the structure of data files (CSV, JSON, Parquet, etc.) for loading or unloading. Example: CREATE FILE FORMAT db.schema.csv_ff TYPE = 'csv';|data loading
17→Storage Integration|A Snowflake object (TYPE=EXTERNAL_STAGE) that securely stores cloud provider credentials for accessing external stages without embedding credentials in stage definitions.|data loading
18→LIST @stage|Snowflake command to list files in a stage. Example: LIST @tasty_bytes.public.s3load; or ls @stage;|DDL command
